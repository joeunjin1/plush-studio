# 제품 편집·저장·견적 서비스 개선안

## 이번 구현

`/#atelier`에서 인형·가방·티셔츠 선택 → 삼면도/윤곽 → 컬러·디자인 → 분리 부위 → 저장·제작 견적 요청을 진행한다.

| 항목 | 구현과 경계 |
|---|---|
| 삼면도 | 가로 한 장을 정면/옆면/뒷면으로 3등분하거나 개별 업로드. 단색/투명 배경 윤곽 추출 후 사용자가 수정한다. |
| 3D | 정면 윤곽+두께로 돌출 모델, 정면+옆면으로 단면 기반 입체 생성. 뒷면은 참고 자료이며 자동 형상 복원에 사용하지 않는다. |
| 가방·티셔츠 | 기본형, cm 단위 가로/세로/두께, 색상, 앞뒤 이미지 디자인의 위치/크기/회전 편집. |
| 추가 부위 | 구·상자·사용자 윤곽 부위, XYZ 위치/크기/회전, 그룹/해제/그룹 이동. GLB에 이름과 개별 메시 보존. 그룹은 불리언 용접이 아니다. |
| 결과 | WebGL 3D 회전, PNG/GLB 내보내기. WebGL 미지원이면 명확히 표시한 2D 정면 대체 화면. |
| 보관 | 이 기기 IndexedDB, 이미지 포함 JSON 백업, 로그인 계정의 비공개 클라우드 저장. 최신 버전 충돌 방지. |
| 요청/관리 | 제출 버전과 이미지 고정, 관리자 열람, 견적 금액·납기·조건 제시, 고객의 최신 견적 동의, 상태 변경 이력. 결제 기능은 아니다. |

## 서비스 개시 전에 필요한 작업

1. Supabase SQL Editor에서 `supabase/migrations/202609060003_customer_requests.sql` 적용 여부를 확인하고 미적용이면 먼저 실행한다. 이어 `202609060004_atelier_projects.sql`을 한 번 실행한다. 004는 재실행용 스크립트가 아니다. 기존 데이터는 삭제하지 않는다.
2. 실제 운영자 계정의 Auth 사용자 UUID를 확인하고 003의 `customer_request_staff`에 등록한다. 이메일 문자열이나 브라우저의 역할 값으로 운영자 권한을 부여하지 않는다.
3. Supabase Auth의 Site URL/Redirect URL에 운영 사이트를 등록하고 이메일 로그인 수신을 실제로 확인한다. Vercel의 공개 Supabase URL/키는 기존 설정을 사용한다. service_role 키를 프론트엔드에 넣지 않는다.
4. 고객 A/B, 관리자 계정으로 실제 이미지 업로드 → 저장 → 다른 기기 재로그인 → 이미지 재열기 → 견적 접수 → 관리자 견적 → 고객 동의까지 확인한다. 테스트 요청임을 표시하고 결제/실제 생산은 진행하지 않는다.
5. 제조용 원본 보관 기능을 별도로 추가한다. 이번 편집 이미지 업로드는 최대 1,200px WebP로 최적화한다. 가로 한 장의 삼면도는 축소 후 나누므로 각 면 해상도가 낮아질 수 있다. 인쇄·자수·봉제 생산 원본의 대체물이 아니다.
6. 결제, 환불, 배송, 세금, 샘플 승인, 발주/생산 상태, 운영자 알림·발송 재시도는 별도 구현·운영 정책 결정 후 개시한다. 견적 동의를 결제 완료로 취급하지 않는다.
7. 요금/업로드 남용 제한, 파일 삭제·보존 기간, 접근 로그, 장애 알림, DB와 파일 백업 및 복원 점검을 운영에 추가한다. 현재 제출 파일은 고객이 변경/삭제할 수 없고 서버 관리 절차가 필요하다.

## 파일은 어디에 보관하는가

- GitHub: 소스, SQL, 문서, 공개용 샘플만 보관한다. 고객 이미지·연락처는 커밋하지 않는다.
- Supabase Database: 소유자, 작업 설정, 버전, 문의, 견적·동의 기록.
- Supabase Storage 비공개 `atelier-assets`: 고객 이미지. 소유자와 해당 문의를 볼 수 있는 관리자에게만 접근을 허용한다. 관리자는 미제출 초안 이미지를 열 수 없다.
- 별도 비공개 백업: DB 덤프와 이미지 객체를 함께 백업하고 실제 재열기까지 복구 훈련한다. Supabase DB 백업에는 Storage 파일 자체가 포함되지 않는다. https://supabase.com/docs/guides/platform/backups

이번 변경은 백업 자동화나 외부 백업 저장소를 개설하지 않는다. JSON 전체 백업은 사용자가 직접 받을 수 있다.

## 검증 기록 및 남은 한계

- TypeScript 검사, Vite 프로덕션 빌드 통과.
- 12개 단위 테스트: 3종 기본형/치수, 앞·옆 윤곽 입체, 잘못된 윤곽 거부, 이미지·부위·그룹 JSON 복구, 입력 검증, 배경 윤곽 추출 등.
- 격리된 PGlite PostgreSQL 환경에서 003/004를 실행했다. 인증/Storage 메타데이터를 모사하여 고객 간 접근 차단, 소유자 검증, 수정 충돌, 초안 이미지 권한, 제출 버전 불변성, 중복 접수 방지, 관리자 견적, 타인/이전 견적 동의 거부, 동의와 이력 접근을 검증했다. 운영 Supabase 테스트와 동일하지 않다.
- 브라우저에서 티셔츠 색상 변경, 기기 저장, 페이지 재접속, 이름·색상·치수 복원을 확인했다.
- 브라우저 파일 업로드는 보안 정책에 의해 거부되어 이미지 업로드부터의 실제 종단 테스트를 수행하지 못했다. 테스트 브라우저는 WebGL 미지원이어서 GPU 렌더링/GLB 다운로드는 실제 기기 추가 검증이 필요하다.
- 연결된 Supabase의 DB 실행 도구가 세션에 노출되지 않아 운영 SQL 적용/실제 계정 격리는 확인하지 못했다. 코드를 배포해도 SQL 적용 전 클라우드 기능은 활성화되지 않는다.

‘완벽한 자동 3D 복원’이나 실물과 동일한 완성 사진을 제공하는 제품이 아니다. 천 주름·재질·봉제·패턴·물성·숨겨진 구조는 별도 모델링과 제조자 검수가 필요하다. 우선 고객이 의도를 명확히 표현하고 동일 버전으로 상담하는 도구로 운영한다.
