# Buyer Order UX Plan — Official Product Personalization

## Product goal

구매자가 “무엇을 주문할 수 있고, 지금 요청한 내용이 어디에 어떻게 적용되는지”를 **한 화면에서 계속 확인**하면서 제작 요청까지 끝낼 수 있어야 합니다. 이 서비스의 주문은 즉시 결제가 아니라, 공식 상품과 개인화 사양을 검토 가능한 요청으로 전환하는 B2B 주문 접수입니다.

> 주문 전에는 탐색의 자유를, 요청 직전에는 사양의 확실성을, 요청 후에는 진행 상태의 투명성을 제공합니다.

## Recommended buyer journey

| 단계 | 구매자 질문 | 입력·행동 | 화면의 핵심 정보 | 로그인 |
|---:|---|---|---|---|
| 1 | 어떤 상품을 주문할까요? | 공식 상품 선택 | 정면·좌·후·우·상 5면, 제품명, SKU, 색상, 검수 상태 | 불필요 |
| 2 | 무엇을 적용할까요? | 상품별 허용 개인화 방식 선택 | 기념택·인쇄·자수 등 가능 방식과 제약 | 불필요 |
| 3 | 어떤 내용인가요? | 문구 입력 또는 로고 파일 첨부 | 글자 수·줄 수·파일 형식, 안전 영역, 공장 검토 기준 | 불필요 |
| 4 | 이 위치·면이 맞나요? | 적용 면 선택 및 프리뷰 검토 | 실제 tag/제품 사진, 수정 버튼, 5면·GLB 참고 전환 | 불필요 |
| 5 | 몇 개를 언제 받을까요? | 희망 수량·희망 납기·용도 입력 | MOQ 안내, 제작 검토 필요 사항 | 불필요 |
| 6 | 누구에게 연락할까요? | 이메일 Magic Link, 담당자·연락처·동의 입력 | 저장되는 요청 요약, 개인정보 동의 | 최종 요청 전 |
| 7 | 요청을 보낼까요? | 단일 확인 버튼 | SKU·상품 버전·개인화 방식·내용·수량·납기·연락처 | 필요 |
| 8 | 다음 절차는 무엇인가요? | 내 요청 확인 | 검토 중 → 견적 → 샘플 → 생산 QA → 운송 상태 | 필요 |

## Screen architecture

### Desktop — proof-first order desk

데스크톱은 3열을 기본으로 합니다. 왼쪽에는 7단계 진행 레일과 이전 단계 이동을 두고, 가운데에는 상품의 5면/GLB와 개인화 결과를 가장 크게 표시합니다. 오른쪽에는 항상 보이는 주문 요약 카드를 배치해 선택한 SKU, 버전, 개인화 방식, 수량, 납기, 현재 검토 상태를 한눈에 유지합니다. summary 내부의 “수정”은 해당 단계로만 돌아가게 하며 입력을 초기화하지 않습니다.

### Mobile — preview first, one decision at a time

모바일에서는 상품 프리뷰를 상단에 유지하고, 한 화면에는 하나의 질문만 보여줍니다. 화면 하단에는 안전 영역을 반영한 고정 CTA를 두어 `다음` 또는 `요청 내용 확인`을 한 손으로 누를 수 있게 합니다. 개인화 방식 선택은 bottom sheet, 주문 요약은 접히는 summary drawer로 제공합니다. 모든 주요 버튼·선택지는 최소 44px 터치 영역을 보장하고, 이메일·수량·전화 입력은 적합한 `type`, `inputMode`, `autocomplete`을 사용합니다.

## Request summary contract

최종 요청은 아래 메타데이터를 immutable snapshot으로 보관해야 합니다. 원본 이미지/GLB/로고 바이트는 DB에 넣지 않고 private storage key와 MIME·바이트 수·checksum만 참조합니다.

| 구분 | 요청 snapshot 필드 |
|---|---|
| 상품 식별 | reference product ID, SKU, 한국어/영문명, 색상, product version |
| 기준 시각 | 5면 image key, model version, model checksum, preview mode |
| 개인화 | profile ID, 방식명, safe-area, text 또는 private asset metadata, 적용 면 |
| 주문 의도 | 수량, 희망 납기, 용도, 추가 메모 |
| 연락·동의 | buyer/company ID, 담당자명, 전화(선택), email, 동의 timestamp |
| 운영 상태 | `received`, 검토 메모, quote/sampling/QA 상태, audit timestamps |

## Validation and trust rules

문구·로고의 즉시 프리뷰는 제작 승인 파일이 아닙니다. 모든 화면에서 “공장 검토 기준”을 짧게 고지하고, 최종 확인 화면에서는 해당 개인화 방식의 제한, 선택 면, 담당자 연락처, 수량·희망 납기를 다시 표시합니다. 대표 제공 GLB는 회전·확대 참고용이고, 5면 사진은 상품 외형의 기준이며, 실측·소재·샘플 검토가 끝나기 전에는 factory-approved digital twin이라고 표기하지 않습니다.

## Staging UAT script

| 시나리오 | 통과 조건 |
|---|---|
| 비로그인 탐색 | 상품·5면·3D·개인화 방식·문구/로고 프리뷰를 로그인 없이 완료 |
| 유효성 검증 | 허용하지 않은 방식, 긴 문구, 잘못된 파일 형식·용량을 즉시 차단 |
| 요청 완결성 | 수량·납기·동의 누락 시 최종 요청이 진행되지 않음 |
| Magic Link 복귀 | 이메일 인증 뒤 입력 상태를 보존하고 최종 요청 단계로 복귀 |
| 요청 기록 | 요청에 SKU·상품/모델 버전·개인화 profile·asset metadata만 저장 |
| 모바일 | 375px와 430px에서 프리뷰가 우선 표시되고 하단 CTA·입력이 가려지지 않음 |
| 운영 인계 | 요청 후 buyer가 내 요청에서 상태를 보고, 운영자가 검토 상태를 변경 |

## Scope sequence

첫 구현은 Bernese memorial plush의 기념택 텍스트/브랜드 마크 방법을 대상으로 합니다. 그 뒤 각 상품에 추가되는 실제 인쇄·자수 방식은 동일 profile contract에 등록해 재사용합니다. Stripe 또는 즉시 결제는 견적·샘플·최종 승인 규칙이 정리된 이후 별도 승인 범위로 다룹니다.
