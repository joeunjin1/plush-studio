# 고객 제작 요청 배포 안내

## 변경 내용

고객 첫 화면은 4단계입니다: 기본형 선택 → 디자인/참고 이미지 → 크기·수량·원단 → 이메일 로그인 및 제작 견적 요청.
제조 작업실은 `#workspace`, 고객 요청 관리는 `#inbox`, 본인 요청은 `#requests`입니다.
내부 제조 화면의 예시 발주·QA·버전 정보는 실제 고객 접수와 별개입니다.

고객 요청은 결제 완료 주문이 아닙니다. 운영자가 제작 가능 여부와 견적을 안내하고 샘플을 확인한 뒤 제작을 확정합니다. 가격·납기 자동 확정, 결제, 자동 상담 이메일은 구현되지 않았습니다.
삼면도와 추가 부위 이미지는 비공개 참고 자료로 저장됩니다. 위치 설명을 포함하지만 자동 3D 재구성이나 편집기에서 임의 부위 결합/분리를 수행하지는 않습니다.

## Supabase: 추가 SQL

기존 001/002를 다시 실행하지 말고 `supabase/migrations/202609060003_customer_requests.sql`만 SQL Editor에서 한 번 실행하세요.
이 파일은 기존 제조 테이블을 변경하지 않습니다. `customer_requests`, `customer_request_staff`, 비공개 `customer-references` 버킷을 추가합니다.

- 고객: 이메일 로그인 후 자기 요청만 조회·접수. 제출 후 디자인/상태를 임의 변경할 수 없음.
- 운영자: 명시적으로 등록한 사용자만 전체 접수 조회와 상태 변경, 이미지 다운로드 가능.
- 이미지: 최대 6장, 장당 5MB. 접수 후 덮어쓰기 금지.
- 요청: 고객별 시간당 최대 10건. 중복 버튼/응답 유실 재시도에 동일 접수 UUID 사용.

운영자로 쓸 계정으로 먼저 사이트에서 로그인하세요. Supabase Authentication > Users에서 해당 사용자의 UUID를 확인한 뒤 다음을 별도로 실행하세요. 이메일을 UUID 대신 넣으면 안 됩니다.

```sql
insert into public.customer_request_staff(user_id)
values ('운영자의-실제-Auth-UUID');
```

`#inbox`에서 상태를 `접수 완료 → 제작 가능 여부 검토 → 견적 안내 → 제작 확정 → 상담 종료`로 변경할 수 있습니다. `견적 안내` 변경만으로 고객에게 메일이 자동 발송되지는 않습니다. 고객이 로그인한 이메일로 개별 상담하세요.

## Auth 설정

Supabase Authentication URL Configuration:
- Site URL: `https://plush-studio.vercel.app`
- Redirect URLs: `https://plush-studio.vercel.app` (테스트 환경은 별도 허용)
- Email 로그인 활성화. 이메일 템플릿은 로그인 링크가 포함된 기본 Magic Link 사용.
- 실제 고객에게 이메일을 보내려면 프로젝트의 SMTP 발송 설정/발송 가능 대상 제한을 확인하세요.

연락처는 브라우저 자동 저장 대상이 아닙니다. 로컬 자동 저장 및 JSON 다운로드에는 디자인·수량·원단·요청 메모만 포함됩니다. 참고 이미지는 새로고침 시 재첨부해야 합니다.

공개 접수를 시작하기 전 사업자 연락처와 운영자에게 맞는 개인정보 처리 안내/보관 정책을 준비하세요. 운영자는 목적이 끝난 요청·이미지와 접수 실패로 남은 미참조 이미지의 보관/삭제를 관리해야 합니다. 자동 보관 만료는 이 마이그레이션에 포함하지 않았습니다.

## Vercel

기존 GitHub 연결, 프로젝트 이름, 도메인을 유지합니다.
- Production Branch: `main`
- Build: `pnpm build`
- Output: `dist/public`
- Install: `pnpm install --frozen-lockfile`
- Vercel 환경변수: `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` 또는 `VITE_SUPABASE_PUBLISHABLE_KEY`
- `service_role` 키를 `VITE_` 변수에 넣지 마세요. 이 화면에는 관리자 비밀키가 필요하지 않습니다.

환경변수 변경 후 새 배포를 해야 Vite 번들에 반영됩니다. SQL 적용 없이 프런트엔드만 배포하면 디자인은 사용할 수 있으나 접수·조회는 실패합니다. 실패 시 접수 완료로 표시하지 않습니다.

## 운영 확인

1. 기본형 선택 및 비율/색상/크기 변경, JSON 저장/복구.
2. 서로 다른 두 고객 계정으로 로그인. A 고객 요청이 B에서 조회되지 않는지 확인.
3. 참고 이미지 첨부 후 실제 테스트 요청 1건 제출, 접수번호·내 요청 확인.
4. 운영자 계정으로 `#inbox`에서 이미지 다운로드 및 상태 변경.
5. 운영자 외 계정의 전체 요청 조회·상태 변경 거부 확인.
6. 휴대폰에서 4단계 진행 및 이메일 로그인 링크 복귀 확인.

WebGL이 없는 기기에서는 2D 정면 일러스트를 표시합니다. 원근/회전은 WebGL 지원 기기에서만 제공됩니다. GLB는 cm를 m로 환산하고 부위에 고유한 이름을 부여합니다.

## 이번 변경의 검증 기록

- TypeScript 검사와 Vercel용 프로덕션 빌드 통과.
- 입력/동의 검증, 원가 계산, 고유 부위 이름·고양이 형상·GLB 미터 환산 등 단위 테스트 10건 통과.
- 별도 PGlite PostgreSQL 환경에 Auth/Storage 인터페이스를 구성해 마이그레이션 실행 및 RLS 검증: 고객 A/B 격리, 운영자 상태 변경, 고객의 제출 필드/상태 변경 금지, JSON null 거부, 이미지 접근/덮어쓰기 제한 통과. 실제 Supabase 적용을 대신하지는 않음.
- 브라우저에서 기본형/색상 변경, 단계 이동, 잘못된 수량 차단, 최종 확인, 390px 모바일 레이아웃 확인.
- 원래 저장소에 있던 운영 서비스 연결 테스트 7건은 로컬에 GitHub/Supabase 인증 환경변수가 없어 실패. 운영 DB 스키마/SMTP/로그인 및 실제 접수 성공은 SQL 적용 후 확인 필요.
- 이 검사 브라우저는 WebGL이 비활성화되어 2D 대체 화면을 검증했으며 GPU 3D 렌더링은 실기기 확인 필요.
